01

设计原则

五条原则，按优先级排列。冲突时上位原则优先。

  • 暖白不纯白。页面底色一律 #FBF8F3，纯白 #FFFFFF 只允许出现在卡片面。纯白底会让整个站"冷"下来，这是最初改版的原因。
  • 留白优先于装饰。区块上下留白不小于 64px，宁可少放一个元素，也不把内容挤在一起。留白是排版的一部分，不是浪费。
  • 发丝线代替阴影。分区靠 1px 描边完成；阴影只用于真正浮起的层（浮动按钮、抽屉）。静止元素不用阴影。
  • 只有两种字重。400 与 500。层级靠字号与颜色拉开，不靠加粗。
  • 动效只做位移与透明度。不缩放、不发光、不旋转（印章例外）。安静是这套风格的优点，不要用动效炫技。
推荐做法

用 --hair 发丝线分隔文章列表；用木色下划线标记当前导航项；用拱形相框承载图片。

避免做法

给卡片加投影做层次；用圆角矩形色块堆满页面；用渐变按钮；用三种以上强调色。

04

排版

十档字号，两种字重。行高比常规更松——这是"暖"的另一半来源。

令牌字号行高字重用途
--fs-displayclamp(32–50px)1.26500首屏主标题，每页仅一处
--fs-h222px1.75500区块标题
--fs-h317px1.75500卡片标题、文章列表标题
--fs-h415px1.75500小标题、姓名
--fs-lg16.5px1.9400导语、正文强调段
--fs-body16px1.75400正文
--fs-sm13.5px1.75400辅助说明、日期
--fs-xs12.5px1.75400mono 数字、时间戳
--fs-cap12px—400标签、徽章
--fs-micro11px—400图注、角标（最小可用字号）
  • 行宽。导语与说明 ≤ 46ch；文章正文 ≤ 72ch（约 720px，用 .wrap-narrow）。超过 75ch 阅读会疲劳。
  • 中英混排。中英文之间留一个半角空格；数字与英文用等宽数字 tabular-nums 保证纵向对齐。
  • 标点。中文用全角标点，英文与代码用半角；不用全角空格做缩进；引号在中文语境用「」，英文用 ""。
  • 字号下限。正文不小于 13.5px，任何文字不小于 11px。
  • 字重。只有 400 与 500。禁止 600 / 700；需要强调时用颜色或 .hl 高亮。
05

间距与布局

全部间距取自 4px 基准阶梯，共九档。不出现阶梯外的数值。

令牌值典型用途
--sp-14px图标与文字之间
--sp-28px同行元素、标签间距
--sp-312px标签与输入框之间
--sp-416px卡片内边距（小）
--sp-524px卡片内边距、栅格间距
--sp-632px元素组之间
--sp-748px小节之间
--sp-864px区块间距下限
--sp-988px大区块上下留白
容器
  • --maxw 1080px · 通用内容容器
  • --maxw-narrow 760px · 长文正文
  • --gutter 32px · 桌面左右留白
  • --gutter-sm 22px · 移动端左右留白
栅格与断点
  • 列数：2 / 3 / 4 列，间距 --sp-5（24px）
  • > 900px 完整布局，侧栏 + 主内容
  • ≤ 900px 侧栏塌陷，4 列降为 2 列
  • ≤ 860px 全部单列，导航折叠为抽屉
可以

用 --sp-* 令牌；用 gap 控制栅格间距；用 padding 撑开容器。

禁止

出现 13px / 27px 这类阶梯外数值；用 margin 负值做布局；用全角空格或 <br> 制造间距。

06

形状

圆角克制、描边极细、阴影几乎不出现——这是"简约"在形状上的定义。

--r-md 12px卡片、提示块
--r-lg 18px大容器、订阅区
--r-xl 26px大面板
--r-full按钮、标签、头像
描边
--bw-hair 0.5px卡片与容器轮廓
--bw-line 1px分隔线、图标描边
--bw-focus 2px焦点环、引用竖线

描边颜色只用 --hair 三级，禁止用色板色做细边框。

阴影
--shadow-sm卡片悬停
--shadow-md浮动按钮、回到顶部
--shadow-lg模态、抽屉

静止状态一律不用阴影。阴影只证明"这一层浮起来了"。

08

装饰图形

装饰是这套风格的"温度"来源，但密度必须严格控制。它的作用是填空白，不是抢内容。

规则定义
画布48 × 48，线性图标，1.3px 描边，圆头圆角，fill:none
颜色继承 currentColor：默认 --wood-deep；次要 --sage-deep；极淡用 --ink + 35% 不透明度
尺寸只用五档：16 / 24 / 36 / 64 / 120px（.orn-xs … .orn-xl）
密度单屏可见装饰 ≤ 3 处；同一视觉区域不重复同一图形
位置只放容器边缘、四角或空白处；绝对定位的装饰必须 pointer-events:none
底纹点阵 18px / 方格 34px / 横格 30px；同一区块只用一种，且透明度来自 --hair 系列
印章每页最多一个，26s 匀速旋转，位于右下或右上角，不遮挡内容
引用同文档 <use href="#o-xxx"> 引用页面内联精灵，禁止外部 svg 文件

09

动效

四个时长、一条缓动曲线、四个位移值。所有动效只允许改变 opacity 与 transform。

令牌 / 值用途
--dur-1 · 180ms颜色、背景、边框等微反馈
--dur-2 · 220ms默认：按钮、卡片、列表行悬停
--dur-3 · 280ms位移、下划线展开、回到顶部显隐
--dur-enter · 700ms滚动入场（一次性，只播一次）
--easecubic-bezier(.22,.61,.36,1) · 全站唯一曲线
--lift-hover / --lift-card按钮上移 1px / 卡片上移 3px
--shift-enter入场初始位移 14px
  • 幅度上限。悬停位移不超过 4px，箭头位移 3–4px。位移越大越廉价。
  • 同时运动。一个交互只动一个元素，不做连锁动画。
  • 入场。用 IntersectionObserver 触发，元素进入视口后只播一次，不做无限循环。
  • 降级。prefers-reduced-motion: reduce 下禁用全部过渡与动画，入场元素直接显示。
  • 例外。仅印章允许持续旋转（26s 匀速），因为它表达"时间"。
可以

按钮悬停上移 1px 并换边色；列表行悬停背景变白、内边距左移 8px；卡片悬停上移 3px。

禁止

悬停放大、发光、抖动、视差滚动、自动轮播、无限循环动画；对 width/height/top/left 做过渡。

10

无障碍

规范里的对比度表就是无障碍要求的一部分，其余条目如下。

  • 对比度。正文与图标 ≥ 4.5:1；≥18.66px 的大字 ≥ 3:1；--muted-2 只做装饰。
  • 焦点可见。统一用 :focus-visible 的 2px 木色焦点环 + 3px 偏移；任何地方不得写 outline:none 而不给替代。
  • 键盘可达。所有交互元素可 Tab 到达且顺序合理；链接用 <a>、动作用 <button>，不混用。
  • 语义结构。用 header / nav / main / section / footer；一个页面一个 h1，标题不跳级。
  • 当前状态。当前导航项加 aria-current="page"；切换类按钮用 aria-pressed；抽屉用 aria-expanded。
  • 图标按钮。必须带 aria-label；纯装饰的 SVG 加 aria-hidden="true"，图形内的 title/desc 说明用途。
  • 颜色不作为唯一信息。状态同时用文字或图形表达（例如"已上线"徽章带圆点）。
  • 动效尊重偏好。见 09 动效的降级条款。
  • 触控目标。可点区域不小于 40 × 40px。
待补齐：抽屉菜单的 Esc 关闭与焦点陷阱；跳转到主内容的「跳过导航」链接。

命名与代码约定

对象规则示例
类名全小写，连字符分隔，语义化.card · .post-list · .nav-drawer
修饰符基础类 + 连字符后缀.btn-solid · .tag-wood · .grid-3
状态沿用既有约定，不另造.open · .show · .in · .active
工具类只用于间距与布局.mt-4 · .flex · .gap-3 · .center
令牌--{类别}[-{变体}]--wood-deep · --fs-h2 · --sp-5
图标前缀 o-，页面内联精灵#o-sun · #o-sprout
正确的引用方式
<!-- 图标：同文档引用，不引外部 svg -->
<svg class="orn orn-md"><use href="#o-sun"/></svg>

/* 样式：只用令牌，不写死色值 */
.card { border: var(--bw-hair) solid var(--hair); border-radius: var(--r-md); }
.btn:hover { transform: translateY(var(--lift-hover)); }
可以

新增样式写进 style.css 对应小节；新增色值先进 tokens.css；一次性布局微调可用行内 style（仅限 padding / margin / grid-template）。

禁止

行内写颜色或字号；用 !important（reduced-motion 降级除外）；复制粘贴组件样式；引入 Tailwind / Bootstrap 等外部框架；用 id 选择器做样式。

文件结构与交付

Blog/
├─ index.html          首页
├─ components.html     组件与装饰总览（可视化参考）
├─ design-spec.html    设计规范（本页）
├─ DESIGN.md           规范 Markdown 版（交付 / 进仓库）
└─ assets/
   ├─ tokens.css       设计令牌 · 唯一来源
   ├─ style.css        组件样式 · 只消费令牌
   └─ main.js          交互：入场 / 回到顶部 / 抽屉 / 筛选 / 目录高亮
  • 加载顺序。每个页面先引 tokens.css，再引 style.css。顺序颠倒会导致令牌失效。
  • 图标精灵。每个页面在 <body> 顶部内联一份 <symbol> 精灵。跨文件 <use> 在 file:// 下会被浏览器拦截，因此不抽成外部 svg。
  • 新增一个组件。① 在 tokens.css 补齐所需令牌 → ② 在 style.css 对应小节写样式 → ③ 在 components.html 加可视化样例 → ④ 在本页 07 补规则条目 → ⑤ 更新 13 变更记录。
  • 本文档优先级。代码与规范冲突时以本文档为准；需要偏离时先改文档，再改代码。

内容结构规范 · 文章

这一层管"写什么"。它和 04 排版是两回事：排版决定文章长什么样，这里决定一篇文章必须有哪些字段、每个字段写多长。

前置字段（frontmatter）
字段必填长度 / 取值写法要求
title是≤ 30 字陈述句，不用疑问句做标题党；不含站点名
date是YYYY-MM-DD发布日
summary是≤ 60 字列表页与分享卡复用，写"读完能得到什么"
tags是1–3 个从固定标签集里选，不新造同义词
updated否YYYY-MM-DD有实质修改时填，页面显示"更新于"
cover否图片路径16:10；没有就用纯色块，不留破图
series否字符串系列名，同系列按顺序排列
draft否true / false草稿不参与构建
正文结构
  • 开头。前 1–2 段直接讲这篇要解决什么问题，不铺垫、不寒暄。
  • 小节。用 h2 分节，最多两层（h2 / h3），不跳级。每节不超过 4 段。
  • 结尾。给结论或下一步，不写"总之"。
  • 长文。超过 2000 字加目录（.toc），并在 >900px 时粘性跟随。
  • 写法。第一人称；具体数字优于形容词；命令与代码用 code；图片必须有题注；不写"众所周知"。

内容结构规范 · 项目

项目详情页按固定的九个字段写，顺序不得重排——读者是靠位置来定位信息的。 完整范例见 work.html。

#字段必填长度 / 取值写法要求
1一句话定位是≤ 30 字说价值，不说技术。"把读过的书变成可检索的笔记"，不是"基于 Tauri 的笔记应用"
2角色是≤ 12 字你具体做了什么；合作项目必须写清分工
3时间是起止年月进行中的写 2025.03 – 至今
4状态是活跃 / 维护中 / 已归档归档要诚实标注，但不删页面
5技术栈是3–6 个只写真的用了的，不列全家桶
6封面 / 演示图是16:10 一张说明界面或结果；深色截图必须放浅色衬底
7为什么做是2–3 段遇到什么问题、为什么现有方案不行。这是区分"练手"和"真项目"的地方
8关键决策是≥ 2 条每条写"选了什么 + 为什么 + 代价"。代价不写就是没想清楚
9结果数据是≥ 1 项具体数字。没有用户量就写自用天数或处理量
10仓库 / 演示链接是各一个打不开的要标注；没有就不渲染按钮，不留空位
11不足与下一步否1–3 条诚实列局限。这一节最加分，建议都写
自检标准：一个陌生人读完这一页，应该能判断"这个项目解决了我关心的问题吗"以及"这个人会不会写代码"。
可以

"不做云同步，先做本地优先。代价是换电脑要手动搬数据，也放弃了移动端。"——决策、理由、代价齐全。

禁止

"使用了 TypeScript、Tauri、SQLite、Vite、Tailwind……"堆技术栈；"效果很好、用户很喜欢"这类无法验证的形容词；把 README 直接粘过来。

UI 规范 · 详情页

这一层管"长什么样"。详情页是长文阅读场景，所以版式比首页更收敛：一栏正文、一个侧栏、极少装饰。

文章详情页版式
  • 容器 .wrap-narrow 760px；正文 .prose 行宽 ≤ 72ch、行高 1.9
  • 页面标题用 display 降到 32–40px；正文层级 h2 → h3 → h4，不跳级
  • 首段用 .prose-lead（16.5px）与正文拉开
  • 代码块用 .code 或 .prose pre，底 --bg-alt，禁止暗色主题
  • 引用用 blockquote.pull：左侧 2px 木色竖线
  • 图片圆角 12px + 发丝边，题注 11px --muted
  • 页尾顺序：相关文章 → 上一篇 / 下一篇
项目详情页版式
  • 头部两栏（1.5 : 1）：左侧标题区，右侧 .meta-row 六项信息
  • 一句话定位用 .prose-lead，控制在两行内
  • 技术栈用 .tag.tag-line，等宽排列，不换行到第三排
  • 操作区一个实心主按钮（打开演示），其余次要或幽灵
  • 封面 .cover 16:10，内部 .cover-inset 留 24px 浅色衬底
  • 结果数据用 .stats 三栏，紧跟在"结果"小节标题后
  • 侧栏：目录 + 项目信息卡（.tile-tint），>900px 时 sticky
  • 页尾用 .proj-nav 做上一个 / 下一个项目
  • 元信息顺序固定。角色 → 时间 → 状态 → 平台 → 许可 → 体量，不得重排或删减到少于四项。
  • 状态必须用徽章。活跃用 .badge-live（带圆点），维护中用 .badge，已归档用 .badge 加深字色，不用颜色单独表达。
  • 截图统一画框。所有截图必须落在 .cover-inset 里，禁止把深色界面直接贴在暖白页面上。
  • 装饰克制。详情页可见装饰 ≤ 2 处（首页允许 3 处），且不进入正文栏。
  • 空字段。字段缺失时整块不渲染，不留空标题或空占位。
