## 为什么做

我之前的博客用了现成主题，改了三周，最后发现改不动了——不是不会改，是它的样式层
互相纠缠，动一个地方就崩三个地方。于是我决定从零写一套：**只有我能理解的样式层**，
规则少到不用查文档。

另一个动机是：我想验证"不发散的设计系统"到底能做到多小。答案是两个 CSS 文件、
一个设计令牌文件，加起来 2,100 行，就能撑起六个页面。

## 关键决策

### 不用任何 CSS 框架

Tailwind 很好，但它的写法会把样式散进标记里，而我想让"版式规则"集中在一处，
能一眼看完。代价是每个组件都要自己写，前两周很慢。

### 装饰图形全部内联，不引外部文件

图标用页面内联的 `<symbol>` 精灵加同文档 `<use>` 引用。这样零请求、零依赖，
而且 `file://` 打开也不会失效——外部 SVG sprite 在本地文件协议下会被浏览器拦截，
这是我踩过的坑。

### 动效只做位移和透明度

不做缩放、不做发光、不做视差。理由很实际：这类动效在低端设备上会掉帧，
而它们提供的"精致感"其实靠配色和留白就能拿到。

## 技术细节

设计令牌是唯一来源，组件样式只消费令牌，不出现硬编码色值：

```css
:root {
  --bg: #FBF8F3;
  --wood-deep: #C08F5E;
  --r-md: 12px;
  --dur-2: 220ms;
}

.card {
  background: var(--surface);
  border: var(--bw-hair) solid var(--hair);
  border-radius: var(--r-md);
  transition: border-color var(--dur-2) var(--ease);
}
```

写这套的时候顺手做了个校验脚本，比对样式里用到的令牌和令牌文件里定义的是否一致——
后来它帮我抓出了两个拼错的变量名。

## 结果

- 首屏零外部请求，Lighthouse 性能分稳定在 100
- 六个页面共用一套令牌，改一个色值全站生效
- 后来把它整理成了正式的设计规范，反过来约束自己的新页面

## 不足与下一步

1. **没有深色模式。** 暖白是这个模板的立身之本，但确实有人习惯暗色。
2. **正文排版只做了基础。** 脚注、图片放大、代码复制按钮都还没有。
3. **没有构建流程。** 纯手写意味着新增页面要复制粘贴，文章超过二十篇就该上静态站生成器了。
